GitHub token

The extension calls the GitHub API with a personal access token (PAT). Approvals and merges are made as the token's owner.

Creating a token

Fine-grained: create a token with the organization as resource owner, access to the repositories you review, and these repository permissions:

  • Pull requests: Read and write to read stacks and approve.
  • Contents: Read and write to merge.
  • Metadata: Read, which GitHub adds automatically.

An organization admin may need to approve a fine-grained token before it works.

Classic: create a token with the repo scope, then use Configure SSO on the token list to authorize it for SAML-protected organizations.

How actions work

  • The PR page reads the stack, head SHAs, reviews, and merge state from GitHub's GraphQL API.
  • Approve submits an APPROVE review pinned to the head SHA shown, and refuses if the PR has moved since.
  • Merge uses GitHub's asynchronous merge API with the expected head SHA, so GitHub cancels it if the branch changes. Only the base-most open PR in a stack can be merged.
  • GitHub still enforces branch protection, required checks, and merge queues.
  • The token is kept in this Chrome profile's extension storage and sent only to api.github.com.
